# D-06 기존 합방 복제 일정 검토안

상태: **미결정**. 운영 DB의 후보 목록을 아직 읽지 못했다. 이 문서는 자동 병합 지시가 아니다.

## 확인된 구현과 영향

- 신규 합방은 주최자 일정 문서 하나에 `memberIds`를 저장하고 참여자 달력에서도 같은 ID를 조회한다.
- 기존 문서는 참여자별 복제본일 수 있다. 전체 달력에는 복제본이 각각 보이고, 같은 제목·시각에 서로를 참여자로 가리키는 복제본이 있으면 수정 API가 충돌을 반환한다.
- 기존 일정에는 원본 그룹 ID나 게시 출처·변경 이력이 없을 수 있다. 합칠 때 어느 내용을 보존할지 데이터만으로 확정할 수 없다.

## 읽기 전용 조사

`apps/back-end/scripts/audit-legacy-schedules.js`가 같은 `title`·`startAt`을 가진 문서 그룹을 후보로 출력한다. 후보는 중복 확정이 아니다. 담당자가 각 그룹에서 ID, 주최자, `member`/`memberIds`, 날짜·종료 시각, 분류, 본문, 방송 링크와 확인 가능한 원문 출처를 비교한다. 제목이나 시각이 다른 복제본도 있을 수 있으므로 이 결과만으로 누락이 없다고 판단하지 않는다.

## 제안하는 원본 선정 기준

1. 같은 행사임을 원문 출처와 참여자 관계로 확인한다. 확인되지 않으면 별개 일정으로 둔다.
2. 주최자가 명확하면 그 주최자의 문서를 원본 후보로 삼는다. 주최자가 불명확하거나 복수이면 관리자가 원문을 확인해 결정한다.
3. 필드가 다르면 최신 수정 시각만으로 고르지 않는다. 제목·시간·본문·공식 여부를 출처별로 대조하고, 공식 방송 판정은 D-01에 따라 관리자가 확인한다.
4. 원본과 제거 대상 ID, 필드별 선택 근거, 출처, 검토자를 기록한 승인 목록을 만든다. 승인 목록 밖 문서는 변경하지 않는다.

## 이전과 되돌림 절차 제안

1. 쓰기 전에 대상 문서 전체와 ID를 별도 백업하고 건수·해시를 기록한다. 운영 DB를 테스트 대상으로 사용하지 않는다.
2. 격리 DB에 백업을 복원해 승인 목록만 적용한다. 원본의 `memberIds`를 확인된 참여자 ID로 채우고, 복제본 제거 후 주최자·참여자 달력의 일정 ID와 날짜별 건수를 비교한다. 변경 이력을 임의로 소급 생성하지 않는다.
3. 원본·복제본의 변경 시각이 검토 때와 같음을 재확인한 뒤 운영에 적용한다. 불일치하면 해당 그룹을 건너뛰고 재검토한다.
4. 되돌릴 때는 해당 그룹의 적용 후 문서를 제거하고 백업한 원본 문서를 원래 ID로 복원한다. 같은 기간의 새 수정·제보 승인이 있으면 먼저 충돌을 조사하고 덮어쓰지 않는다. 복원 후 건수와 달력 결과를 백업 전 기록과 비교한다.

## 결정이 필요한 내용

- 운영 데이터에서 실제 후보와 원문 출처를 확인한 뒤, 그룹별 원본 및 제거 대상 승인.
- 중복 문서를 삭제할지 별도 보관할지, 보존 기간과 담당자.
- 공개 달력 중복 해소를 위해 이전할 기간·범위.
