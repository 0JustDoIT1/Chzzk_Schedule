# 0군의 삶 — 제품 요구사항

> 기준선 v0.3 · 2026-11-12. 이 문서는 제품 목표와 요구사항을 정의한다. 현재 구현·검증 상태는 [DEVLOG](./DEVLOG.md)에 기록한다. `확정`은 대화에서 합의된 방향이고 `미결정`은 구현만으로 정책을 확정할 수 없는 항목이다.

## 1. 목적과 사용자

치지직 스트리머의 **예정된 방송 일정**을 날짜, 스트리머, 공식 방송 기준으로 찾게 한다. 방문자는 일정을 조회하고 제보한다. 관리자는 출처와 중복을 검수해 게시·반려한다.

### v1 핵심 흐름

1. 방문자가 오늘 또는 월간 일정과 상세 내용을 조회한다.
2. 방문자가 스트리머 또는 일정을 출처 링크와 함께 제보한다. 접수 직후 공개 일정은 바뀌지 않는다.
3. 제보자는 무작위 확인 주소에서 대기·승인·반려 상태를 조회한다.
4. 관리자가 제보 내용과 출처를 검토하고 승인 또는 반려한다. 승인 시 공개 데이터가 바뀐다.
5. 게시 일정의 변경도 제보·검수를 거친다. 검수 전에는 기존 게시본이 유지된다.

### 범위

| 구분 | v1 기준 |
| --- | --- |
| 화면 | 한국어 웹, 한국 시간(KST) 중심. 오늘·전체·스트리머별·공식 방송의 캘린더/타임라인과 상세 |
| 데이터 | 출처를 가진 수동 제보와 관리자 게시. 예정 일정과 현재 라이브를 별개로 취급 |
| 후속 범위 | 관심 스트리머, 알림, 실시간 라이브 표시, VOD·채팅 연동 |

## 2. 확정된 정책과 불변조건

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| P-01 | 공개 조회, 공개 제보, 관리자 검수 후 게시 | 인증 없는 직접 생성·수정 API 호출은 거부되고, 미승인 제보는 공개 조회에 없다 |
| P-02 | 제보와 게시 데이터를 분리 | 접수 성공은 게시 성공으로 표시하지 않는다. 공개 상세 ID와 제보 확인 토큰은 별개다 |
| P-03 | `공식 방송`은 방송의 범주 | 치지직이 이 서비스 데이터를 인증했다는 의미로 표시하지 않는다. 제보자의 선택만으로 공식 게시하지 않는다 |
| P-04 | 합방 일정의 단일 원본 | 새 방송 행사는 일정 문서 하나로 관리하고 참여자별 화면은 같은 원본 ID를 표시한다 |
| P-05 | 기존 복제 데이터 보존 | 확인되지 않은 기존 일정을 자동 병합·삭제하지 않는다. 후보 조사와 수동 검토 후 이전한다 |
| P-06 | 관리자 비밀값 서버 보관 | 브라우저 번들에 관리자 API 토큰·Client Secret을 넣지 않는다 |

### D-01 확정: 공식 방송 판정

- `공식 방송`은 **치지직이 직접 주최했거나 치지직 공식 채널이 공지한 방송 일정**이다. 일반 스트리머의 공지·합방·팬 제보는 치지직 공식 방송으로 분류하지 않는다.
- 스트리머의 인증 마크, 채널명, 현재 라이브 여부만으로 공식 방송이라고 판단하지 않는다. 제3자가 공식 공지를 재게시한 링크도 단독 근거로 쓰지 않는다.
- 검수자는 치지직의 직접 공지·공식 채널 게시물처럼 확인 가능한 원문 링크를 열어 제목·날짜·주최를 확인한다. 근거가 불충분하면 일반 분류로 게시하거나 반려한다.
- 방문자는 공식 여부를 선택하지 않는다. 관리자만 검수 화면에서 공식 콘텐츠 또는 공식 같이보기로 분류하고, 출처 확인을 명시한 뒤 게시한다. 분류와 공식 여부가 서로 다르면 서버가 거부한다.
- `공식 채널`이라는 스트리머 속성과 `공식 방송`이라는 일정 속성은 별개다. 공식 채널에서 진행하는 모든 방송이 공식 편성 일정인 것은 아니다.

## 4. 데이터와 연동 경계

- 공개 스트리머 식별자는 장기적으로 치지직 `channelId`를 우선한다. 현재 이름·링크 중심 데이터에서의 이전 방법은 미결정이다.
- 신규 일정은 주최 스트리머 ID와 참여 스트리머 ID를 연결한다. 기존 이름 기반 `member`와 복제 문서는 이전 대상이다.
- 일정 시각은 KST로 입력·표시하고 저장 형식은 시간대가 명확해야 한다. `시간 미정`, `종료 미정`, `종일`은 별도 상태로 정의해야 한다.
- 치지직 [공식 API](https://chzzk.gitbook.io/chzzk)는 채널 정보와 현재 라이브 목록을 제공한다. 확인한 [채널](https://chzzk.gitbook.io/chzzk/chzzk-api/channel)·[라이브](https://chzzk.gitbook.io/chzzk/chzzk-api/live) 문서에는 미래 편성표 조회가 없어, 예정 일정 자동 수집을 v1 전제로 두지 않는다. API 사용 시 [앱 등록·인증 규격](https://chzzk.gitbook.io/chzzk/chzzk-api/tips)을 따른다.
- 비공식 내부 API와 스크래핑은 현재 공급원으로 채택하지 않는다. 별도 검토 없이 기능 범위에 포함하지 않는다.

## 5. 공개 전 완료 조건

1. 공식 방송의 정의, 인정 가능한 출처, 시간 미정·취소 처리 규칙을 결정한다.
2. 기존 복제 일정 후보를 읽기 전용으로 조사하고, 백업·이전·되돌림 절차를 승인된 목록에 대해 검증한다.
3. 익명 제보 남용과 관리자 로그인 시도를 여러 서버 인스턴스에서도 제한한다. 관리자 계정·권한·감사 기록을 정한다.
4. 일정 생성·수정·반려·중복·날짜 경계의 격리 DB 테스트, 프런트 빌드, 배포·백업·오류 관측을 통과한다.
5. 화면 문구·SEO 메타데이터·개인정보 처리 범위를 실제 운영 방식과 일치시킨다.

## 6. 미결정 사항

### D-08 확정: 게시 출처와 변경 이력

- 관리자는 일정 게시·수정 승인 시 `http(s)` 출처 URL을 확인하고 저장한다. 수정 승인에는 공개 변경 요약을 반드시 적는다.
- 공개 일정 상세에는 현재 출처와 게시·수정 시각, 변경 요약, 변경된 필드 이름, 해당 승인에 사용한 출처를 최신순으로 표시한다.
- 기존 일정에 출처·이력이 없으면 출처 미기록으로 표시하며 과거 이력을 추정해 생성하지 않는다.
- 현재 관리자 인증은 공유 비밀번호 방식이므로 개인 검수자 신원은 기록하지 않는다. 계정별 감사 기록은 D-05에서 결정한다.

| ID | 결정할 내용 | 결정 전 영향 |
| --- | --- | --- |
| D-02 | 출처 없는 제보를 접수·게시할지 | 제보 폼과 검수 규칙 |
| D-03 | 시간 미정·종료 미정·취소의 데이터/화면 규칙 | 스키마·날짜 조회·캘린더 표시 |
| D-04 | 제보자에게 반려 사유를 보여줄지 | 확인 토큰의 정보 범위 |
| D-05 | 관리자 수, 역할, 운영 주기와 처리 목표 | 인증·감사·검수 UI |
| D-06 | 기존 복제 일정의 원본 선정·이전 범위 | 기존 달력 중복·수정 제한 |
| D-07 | 스트리머 `channelId` 이전 시 이름 변경·충돌 처리 | URL·조회 API·기존 링크 |
| D-09 | 익명 제보 요청량·중복 제한과 운영 대응 | 공개 API 남용·저장 비용 |

### D-03 검토안: 시간 미정·종료 미정·취소

아래는 구현 전 검토할 **제안**이며 확정 정책이 아니다. 현재 저장 모델은 `startAt`·`endAt`을 필수로 요구하고, 월간 조회는 두 시각으로 포함 날짜를 계산한다. 따라서 미정 시각에 `00:00`이나 임의 종료 시각을 넣어 실제 시각처럼 표시해서는 안 된다.

| 입력 상황 | 제안하는 데이터·검증 | 공개 화면 |
| --- | --- | --- |
| 시작 날짜·시간과 종료 시간 확정 | 기존 시각 저장. 종료가 시작보다 늦어야 한다 | 실제 시작·종료 시각 표시 |
| 시작 날짜만 확정 | 날짜는 별도 KST 달력 날짜로 보존하고 시작 시각은 미정으로 표시 | 해당 날짜에 `시간 미정`으로 표시하고 시각순 목록 뒤에 배치 |
| 시작 확정, 종료 미정 | 종료 시각 미정 상태를 별도로 보존하고 달력 표시 날짜를 임의로 늘리지 않는다 | `종료 미정` 표시. 날짜별 노출 범위는 아래 선택 필요 |
| 종일 | 날짜 범위로 표현한다. 시간 미정과 구별한다 | 시각 대신 `종일` 표시 |
| 취소 | 일정을 삭제하지 않고 상태와 확인된 근거·변경 요약을 기록한다 | 상세와 달력에 `취소` 표시, 원래 일정과 변경 이력 보존 |

결정 필요: (1) 시작 **날짜조차** 모르는 제보를 접수만 하고 달력에서는 제외할지, 게시 자체를 보류할지, (2) 종료 미정 방송을 시작 날짜에만 표시할지 또는 종료가 확인될 때까지 다음 날짜에도 표시할지, (3) 취소 일정을 달력에 얼마나 오래 노출할지. 제안 기본값은 날짜 미정 제보 접수·게시 보류, 종료 미정은 시작 날짜에만 표시, 취소는 원래 날짜의 달력과 상세에 계속 표시하는 것이다. 기존 일정에는 확정 시각·예정 상태를 기본 해석으로 적용하고 자동으로 미정·취소로 바꾸지 않는다.

## 7. 다음 기획 검토 순서
